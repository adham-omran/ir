* Learned
- Org 9.7+ routes =org-id-get= through =org-element-at-point=, which errors in non-Org buffers ("rx ** range error"); guard with =(derived-mode-p 'org-mode)=.
- =org-roam= advises =org-id-find= (=:before-until=, org-roam-id.el:62), so =org-id-open= resolves roam ids from the roam db — but only when org-roam is loaded.

* Pending: file-level-node narrow fix (specced, not implemented)
** Root cause (confirmed, reproduced)
=ir--reading-setup= calls =org-narrow-to-subtree= unconditionally.
A file-level Org-roam node (=:ID:= in a top property drawer, no =*= heading) has
no subtree, so =org-narrow-to-subtree= raises =outline-before-first-heading=.
The over-broad =condition-case= reports this as "cannot open" and prompts to
delete a *valid* row; =org-id-open= itself succeeds (the file opens).
Affects ~all file-level nodes (observed on an 811-item roam queue).
Until fixed, answer =n= (never =y=) to the prompt — the rows are valid.

* Also pending: (ir-done-and-delete) (researched, not specced)
Mark the item at point done, delete the original file, and delete its db row.
Blocked on file-vs-heading semantics: a file-level node maps 1:1 to a file (safe
to delete), but a heading item (extract, plain heading) shares a file, so
deleting "the original file" destroys the source/siblings. Open forks: unit of
"the file" (file-level only vs delete subtree for headings), "done" meaning
(pure delete vs log), trash vs permanent, confirmation, collateral cleanup
(orphaned sibling rows, stale =org-id-locations= / roam db, live buffer).
