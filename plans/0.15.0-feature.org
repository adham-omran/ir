* Goal
Gate the queue commands behind an explicit session and add =(ir-set-priority)=.
- All commands except bootstrap (start + add*) require an active session.
- =(ir-set-priority)= sets =priority= on the item under review (=ir--current-id=).
- =(ir-end-session)= concludes with a summary line.
- Remove =(ir-view)= and the =(ir-delete)= command.

* Decisions locked
| Fork                 | Resolution                                                              |
|----------------------+-------------------------------------------------------------------------|
| D1 gating scope      | Maximal — every non-bootstrap command gated behind a session           |
| D2 session state     | Explicit flag + read counter (+ start-time for duration)               |
| D3 end summary       | =N items read in H:MM, K still due= — no completion count              |
| D4 priority entry    | =read-number=, hint "Set priority (0 is highest)", clamp to [0,100]    |
| D5 session model     | Binary active/not; end is terminal; no resume                          |
| Target item          | =ir--current-id= only; point fallback dropped everywhere               |
| Removals             | =ir-view=, =ir-delete= (command); =ir--delete= helper kept             |
| Version              | bump minor 0.14.0 → 0.15.0                                              |

* Confirmed mechanics (verified in-session)
- =ir--delete= helper retained — callers at ir.el:376,539,556 survive the =ir-delete= command removal.
- =ir-navigate-to-heading= / =ir-edit= / =ir-open= have no internal callers — safe to gate.
- =ir--format-time= is orphaned by =ir-view= removal (sole caller ir.el:466) — remove it.
- =ir--select= / =ir--columns= retained — used at ir.el:146,150,332.
- =priority= is a pure order key (=ORDER BY priority ASC=, ir.el:334) — set-priority needs no reschedule.
- Counter site: =ir--reschedule-current= success branch (ir.el:223-224) fires from both =ir-read-next= and =ir-end-session= → the last item counts (N3a).

* Contract
- pre: =ir--session-active= for all gated commands; additionally =ir--current-id= non-nil for read-next / set-priority / done-and-delete.
- post: a gated command outside a session signals =user-error= and mutates nothing; =ir-end-session= reports the summary and clears all session state.
- invariant: =ir--current-id= is the sole target of in-session item commands (no point fallback); bootstrap commands (start, add*) are never gated.
