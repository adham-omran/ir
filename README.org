#+title: ir.el - Incremental Reading

The term is orginally coined by Piotr Wozniak and he describes it as:
#+begin_quote
Incremental reading is a learning technique that makes it possible to read
thousands of articles at the same time without getting lost. Incremental reading
begins with importing articles from electronic sources, e.g. the Internet. The
student then extracts the most important fragments of individual articles for
further review. Extracted fragments are then converted into questions and
answers. These in turn become subject to systematic review and repetition that
maximizes the long-term recall.
#+end_quote
[[https://super-memory.com/help/read.htm#Introduction_to_incremental_reading][Introduction to Incremental Reading]]

This project covers the useful features of incremental reading over *Org
material only* — plain Org headings and Org-roam nodes. The main features are
*scheduling of material* (a SuperMemo-style topic algorithm) and *in-place
extraction* of fragments into scheduled child headings.

The current way to create questions and clozes out of the extracts is to write
them out using [[https://www.github.com/adham-omran/ankifier][ankifier.el]]. PDF incremental reading now lives in a separate
application and is no longer part of this package.

* Tutorial
** Add material
- Put point on any Org heading (plain Org or an Org-roam node) and run =M-x ir-add= to queue it.
- =M-x ir-add-roam-node= queues an Org-roam node chosen by title.
- =M-x ir-add-roam-directory= queues every Org-roam node at once.
- While reading, select a region and run =M-x ir-extract-region= to carve it into a scheduled child heading (the parent text is kept).

** Read on a schedule
1. =M-x ir-start-session= opens the most-due item and narrows you into it. Run it from anywhere.
2. Read the item. Extract fragments with =ir-extract-region= as you go.
3. =M-x ir-read-next= records this item (advances its interval) and opens the next. Run it from within the item — the session keeps point there.
4. Repeat until you see "queue empty for today".
5. =M-x ir-end-session= records the last item and ends the session (closing the session frame if =ir-session-in-new-frame= is set).

If =ir-start-session= reports "cannot open ... id not indexed" for Org-roam
nodes, sync the Org-roam database with =M-x org-roam-db-sync= so the ids
resolve.

** Implementation of question creation
I see no reason to implement a way to create basic or cloze questions. This is
not SuperMemo and I've already worked out a way to create basic and cloze cards
using [[https://www.github.com/adham-omran/ankifier][ankifier.el]].
** Why =(ir-open)= deletes other windows?
Since you are not supposed to manually open material. (ir-open) assumes you want
to take notes on a specific piece of material. So it sets up the frame for that.
My suggestion is to start a session then use (ir-open) then end the session when
done with the manual study.
* Design of the Database
Using the built-in ~sqlite.el~ the schema is:

| Column        | Affinity | Description                                  |
|---------------+----------+----------------------------------------------|
| id            | TEXT     | Unique ID using ~org-id~ (primary key)         |
| afactor       | REAL     | [[https://super-memory.com/help/g.htm#A-Factor][A-Factor]], default 1.2                       |
| interval      | INTEGER  | [[https://super-memory.com/help/g.htm#Interval][Interval]] in days (informational)            |
| priority      | REAL     | [[https://super-memory.com/help/g.htm#Priority][Priority]]; 0 = most important … 100 = least |
| due           | INTEGER  | Unix time of next repetition                 |
| last_reviewed | INTEGER  | Unix time of last review                     |

Every item is an Org heading addressed by its ~org-id~; there is no file-type
column. Content lives in your Org files (plain or Org-roam) and the database
holds only the schedule.
** Algorithm Design

Scheduling follows SuperMemo's topic model. On review the next interval is the
*real elapsed interval* (time since the last review) multiplied by the A-Factor,
measured from the review day:

$\text{Elapsed} = \text{round}((\text{now} - \text{LastReviewed}) / 86400)$

$\text{Interval} = \max(1, \text{round}(\text{Elapsed} \times \text{AFactor}))$

$\text{Due} = \text{now} + \text{Interval}$

The A-Factor grows by =ir-afactor-increment= (default 0.015) per review. The
review queue is a priority queue: only items with $\text{Due} \le \text{now}$
are eligible, ordered by priority (0% first).
